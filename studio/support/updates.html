Updating to the newest build

New Studio builds land roughly every week. They are small and frequent on purpose — you should feel the program moving.

WhatWhere you'll find it
Update pillTop of the Studio window, when a newer build is available.
Manual downloadThe alpha access page
What changedRelease notes

The update pill

The Studio checks for a newer build in the background. When it finds one, a small pill appears at the top of the window with the version number and a line or two about what changed. Click it and you are taken to the installer.

The check is silent when it fails. If you are offline, or the update service is having a bad day, the Studio simply does not mention it — you will never get an error loop about updates.

Installing an update

  1. Save your work and close the Studio.
  2. Run the downloaded installer. It replaces the installed copy in place.
  3. Reopen. Your preferences, keyboard shortcuts, object defaults, and recent projects all survive.
You never need to uninstall first, and you should not — a clean install and an upgrade end up in the same place, but the upgrade is faster and keeps your settings.

Getting a build by hand

If the pill never shows up, the alpha access page always links the current installer. Downloading from there is exactly the same file the pill would have given you.

Which build am I on?

Help → About SprinkFlow… shows the version. That number is the single most useful thing to include when you tell us something is broken — and a bug report filed with F12 attaches it for you automatically.

Things move between builds. A menu item can be renamed, a panel can move, and occasionally a half-finished feature is pulled back out while it gets rebuilt. That is what alpha means here — the release notes are the running record.
